# NEXUS OSINT

Первый срез настольного приложения для Arch Linux и Hyprland. Интерфейс реализован на Qt Widgets через PySide6. Данные хранятся в SQLite, полнотекстовый поиск использует FTS5. FastAPI и сетевой сервис для самого приложения не требуются.

Ход разработки и результаты проверок записаны в [DEVELOPMENT.md](DEVELOPMENT.md).

## Установка и запуск

В каталоге проекта выполните:

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
bash launch.sh
```

Скрипт выбирает Qt Wayland. База находится в `$XDG_DATA_HOME/nexus-osint/projects.sqlite3` или `~/.local/share/nexus-osint/projects.sqlite3`. Кнопка «Резервная копия» создаёт отдельный согласованный снимок SQLite. База и её копии хранят содержимое в открытом виде. Удаление проекта очищает данные и поисковый индекс рабочей базы. Ранее созданные копии и экспортированные файлы сохраняются.

## Сценарий

Создайте проект, импортируйте PDF с текстовым слоем, DOCX или UTF-8 документ или запросите DNS A, CT либо IP RDAP. Откройте сохранённый ответ в Evidence Manager. Здесь же можно искать фрагменты по тексту в текущем проекте. В Graph Explorer можно добавить сущность и связь с оценкой достоверности и материалом проекта. Связь без источника сохраняется как гипотеза. Сущности сгруппированы по типам. Доступны фильтры по названию и типу, а также экспорт JSON и GraphML. Экспорт Markdown включает заметки и сохранённые материалы. Сетевые операции выполняются в одном фоновом потоке.

## Перенос расследования

В Dashboard выберите «Экспорт проекта». Файл `.nexus.json` содержит заметки, сохранённый текст материалов, граф и анализ. Импорт открывает отдельную копию и восстанавливает поиск. Исходные пути и URL хранятся как ссылки на происхождение. Исходные бинарные вложения, параметры движков и журнал API при переносе не включаются. Формат ограничен 64 МиБ и хранится в открытом виде.

## Модели

Ollama должен слушать `127.0.0.1:11434`. В Settings можно получить список моделей Ollama, указать модель вручную, настроить системный промпт, температуру и окно контекста. Для OpenAI задайте переменную окружения `OPENAI_API_KEY` в оболочке, которая запускает приложение. Для API нужны отдельные ключ и биллинг. Перед облачным запросом откройте подробности диалога подтверждения, чтобы увидеть текст отправки.

По вопросу подбирается до восьми фрагментов текущего проекта. Режим «Авто» выбирает Ollama и предлагает GPT для длинных или сравнительных запросов. Приложение сверяет дословные цитаты с переданными фрагментами, показывает исходные ссылки и сохраняет утверждения в проекте и Markdown. Смысловой вывод проверяет аналитик. Семантический поиск, агент, автоматическое выделение кластеров, шифрование и OCR файлов ещё не реализованы.

Режим «Гибрид» сначала сохраняет локальный анализ. Для второго этапа выберите модель OpenAI и подтвердите отправку. Предпросмотр включает вопрос, фрагменты источников и локальные выводы. При успешном ответе оба набора утверждений сохраняются с указанием провайдера. При отказе или ошибке GPT локальный анализ остаётся в проекте.

В «Журнале API» видны провайдер, время, длительность и статус последних 250 операций выбранного проекта. Журнал не сохраняет ключи, запросы и тела ответов.

## Проверка

```bash
QT_QPA_PLATFORM=wayland .venv/bin/python -m unittest -v
python -m py_compile app.py core.py
```

Тесты ядра используют временную базу и подмену транспортного уровня для проверки AI-контрактов. Для проверки внешних источников и модели нужны доступная сеть и соответствующая конфигурация.

## Модули публичных источников

Search Hub загружает встроенные модули и точки входа `nexus_osint.sources` из виртуального окружения. Сторонние модули являются обычным Python-кодом с правами приложения. Устанавливайте модули, издателю которых доверяете.

В `pyproject.toml` пакета:

```toml
[project.entry-points."nexus_osint.sources"]
org-catalog = "org_catalog:source"
```

Объект `source` должен быть экземпляром `Source` из `sources.py`. Укажите ID, название, описание, подсказку для ввода, HTTPS-хост, построитель URL и валидатор ответа. Построитель должен проверять входные параметры. Валидатор должен принимать ответ, прошедший схему модуля, и возбуждать `ValueError` при несовпадении. Добавьте тесты для обоих сценариев. При необходимости укажите `key_env`, `key_header` и `key_prefix`. Ключ отправляется в заголовке. Перенаправления для модулей с ключами запрещены.

Один фоновый исполнитель соблюдает минимальный интервал модуля и повторяет временные сетевые ошибки с увеличивающейся задержкой. Небольшие публичные ответы без ключа кэшируются в памяти на две минуты с сохранением исходного времени получения. Журнал отмечает попадание в кэш.
